# Built-in components and universal qualification

These reports cover the implemented SuperDex-specific API, not arbitrary custom
component types or every asset in the bundle. They were produced with a modified
working tree; each report records that fact, the base commit and the asset digest.

| Evidence | Coverage |
| --- | --- |
| `bundle-audit.json` | All 35 bots audited with an effort-limit fallback of 1: 21 passed, 14 explicitly blocked, no failed checks |
| `fr3_v2.json` | Fixed-base torque control |
| `dg5f_short_left.json` | Floating hand torque control |
| `wuji_hand2_beta1_left.json`, `wuji_hand2_beta1_right.json` | Non-actuated Wuji Hand2 variants retain torque support |
| `jsc/fr3_v2.json` | Built-in JSC PD controller |
| `osc/fr3_v2.json` | Built-in OSC PD controller |
| `pose/fr3_v2.json` | Built-in implicit articulated-pose controller |
| `with-sphere/wuji_hand2_beta1_left.json` | Floating hand and rigid scene composition |

The synthetic tests in `tests/test_superdex_component_qualification.py` generate
a closed tetrahedron and camera parameter file locally. They verify translated
and rotated camera mounts, independent controller instances, numerical agreement
with direct SDK execution, both pose-controller target forms, selective reset,
cleanup, malformed inputs, and rejection of missing compiled camera components.
They require the optional SDK but do not require the asset bundle. Separate
SDK-free tests cover unsupported types and qualification CLI behavior.

The current SDK rejects OSC initialization on the tested floating-base bot due
to bot/actor effort-limit indexing. The test verifies that same error directly
against the SDK and requires the adapter to report it explicitly. Fixed-base
OSC and fixed/floating JSC and articulated-pose control have numerical tests.

The universal runner requires `--bots` or `--all`. `--effort-limit` supplies
missing authored limits; it is a qualification input, not hardware calibration.
With no `--controller-config`, it applies torque commands generated by a bounded
runner-side PD profile. The JSON files under `configs/` demonstrate each built-in
controller. Use separate `--out` directories when comparing configurations of
the same bot: report names are based on the bot filename.

Pass `--absolute-target` with a matching controller configuration to hold one
explicit absolute command throughout controller qualification. JSC targets are
absolute native actor DOF coordinates. OSC targets are absolute end-effector
poses in the root frame. Articulated-pose targets contain an absolute world root
pose and absolute non-root pose DOFs. SDK transforms use `rotation_xyzw`.
Examples for the fixed-base FR3 live under `targets/`.

`--visualize` opens two live windows: one runs the serial UniSim adapter and the
other runs the direct native SDK path. Separate processes own the two renderers,
and a frame barrier keeps their physics updates synchronized. Close either window,
or press Ctrl+C in the terminal, to stop both. This mode does not write a GIF or a
qualification report. The comparison requires the optional SuperDex viewer with
Polyscope >= 2.5.0 and exactly one `--bots` path. For example:

```bash
uv run --no-sync scripts/superdex_component_qualify.py \
  --bots bots/arms/fr3_v2/fr3_v2.superdex_bot \
  --effort-limit 87,87,87,87,12,12,12 \
  --controller-config docs/superdex-component-qualification/configs/fr3-jsc.json \
  --absolute-target docs/superdex-component-qualification/targets/fr3-jsc-absolute.json \
  --visualize
```

The windows are titled `UniSim adapter` and `Native SuperDex SDK`; the terminal also
prints their process IDs. Place the windows side by side for direct inspection. Repeat
the command with the OSC or articulated-pose configuration and matching target JSON
to compare those controllers. Run the same command without `--visualize` when you
also want the numerical report.

Absent cameras are skipped, not counted as sensor validation. Blocked models
and failed checks produce a nonzero CLI exit status, but `--all` continues to
other models. Reports preserve their original asset digests when documentation
changes later. See [the adapter guide](../superdex.md#built-in-cameras-controllers-and-universal-qualification-stage-6)
for API and coordinate conventions.
